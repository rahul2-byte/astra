Why I Built It & The Core Research Question

              In applied machine learning, claims of "99% parameter efficiency" are often reported without scrutinizing down-stream generalization tradeoffs, gradient stability, or the sensitivity of low-rank updates across datasets of contrasting scale. Parameter reduction alone is an incomplete metric: a model that saves 99% of its weights but drops 18% in pairwise sentence paraphrase accuracy introduces silent failure modes into production pipelines.             

              This reproduction project sought to answer two straightforward engineering questions:             

  • arrow_forward Generalization Parity: Does a custom, cleanly implemented LoRA adapter in PyTorch match the benchmark score of full-parameter fine-tuning on binary sentiment analysis (SST-2, ~67k training examples) within standard statistical error?
  • arrow_forward Data Scarcity Bottleneck: How does rank adaptation degrade when applied to highly constrained, pairwise paraphrase tasks (MRPC, ~3.6k examples) under standard shared hyperparameters, and can a rank sweep (r ∈ {2, 4, 8, 16}) resolve the bottleneck?

System Architecture & Mathematical Formulation

Self-Attention Query/Value Projection Adaptation

                  Rather than modifying the full weight tensor W₀ ∈ ℝ^(d×k), LoRA decomposes the weight update into two low-rank matrices B ∈ ℝ^(d×r) and A ∈ ℝ^(r×k) where r ≪ min(d, k). Base weights remain completely frozen during backward passes.                 

FORWARD FORMULATION ZERO-LATENCY INFERENCE AVAILABLE
                  h = W₀x + ΔWx = W₀x + (α / r) · B A x                 

• Initialization: Matrix A initialized with Gaussian distribution 𝒩(0, 1/r); Matrix B initialized to exact zero (B = 0), ensuring ΔW = 0 at step 0.

• Scaling Constant: Scaling factor α / r (with α = 16) avoids the need to retune hyperparameters when changing rank r.

• Inference Merging: At inference time, W = W₀ + (α/r)·BA is precomputed, yielding 0ms added runtime latency.

Custom LinearLoRA Layer Implementation Python / PyTorch 
# Core low-rank projection layer applied to query & value matrices
class LinearLoRA(nn.Module):
    def __init__(self, in_features: int, out_features: int, r: int = 8, alpha: float = 16.0):
        super().__init__()
        self.r = r
        self.alpha = alpha
        self.scaling = alpha / r
        
        # Frozen base weight matrix
        self.base_layer = nn.Linear(in_features, out_features, bias=False)
        self.base_layer.weight.requires_grad = False
        
        # Trainable low-rank decompositions
        self.lora_A = nn.Parameter(torch.empty((r, in_features)))
        self.lora_B = nn.Parameter(torch.zeros((out_features, r)))
        nn.init.kaiming_uniform_(self.lora_A, a=math.sqrt(5))

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        base_out = self.base_layer(x)
        lora_out = (x @ self.lora_A.T @ self.lora_B.T) * self.scaling
        return base_out + lora_out
check_circle Verification Suite: Automated test suites with pytest verify that outputs from custom merged adapters match Hugging Face PEFT reference implementations to within numerical floating-point tolerances (atol=1e-5).
03

Experimental Protocol & Methodology

            To ensure zero contamination and reproducible findings, all experiments were bounded by strict control rules:           

PHASE 01 lock

Pin Protocol & Datasets

                Fixed model commit hashes for roberta-base. Evaluation restricted exclusively to GLUE validation splits (validation_matched) without using the validation set for tuning or early stopping.               

PHASE 02 alt_route

Tripartite Baseline Regime

                Trained three configurations across three deterministic seeds (42, 1337, 2024): (1) Linear classifier head only, (2) Full parameter fine-tuning, and (3) Custom LoRA adapters on attention projections.               

PHASE 03 query_stats

Full Cost Accounting

                Instrumented exact PyTorch CUDA peak memory allocation tracking via torch.cuda.max_memory_allocated(), measuring end-to-end wall-clock training durations and exported serialization artifact sizes on disk.               

PHASE 04 biotech

Single-Seed Rank Ablation

                Conducted 8 dedicated single-seed ablations across rank hyperparameters r ∈ {2, 4, 8, 16} and scaling alpha values α ∈ {8, 16, 32} on MRPC to diagnose performance sensitivity on low-sample classification.

analytics Critical Technical Insight: MRPC Low-Rank Failure Mode

                While SST-2 validated the efficiency premise of LoRA by achieving empirical parity with full fine-tuning, MRPC exposed an acute operational bottleneck. Under identical learning rates (2e-5) and epoch budgets (3 epochs), LoRA collapsed toward majority class guessing on MRPC.               

                Because MRPC comprises only ~3,668 training pairs with a 68% positive class imbalance, a restricted rank subspace (r=8) on query and value projections alone provided insufficient expressive capacity for cross-sentence attention alignment within 3 epochs. The model optimized cross-entropy loss by predicting the positive class indiscriminately—resulting in a deceptively respectable F1 score of 0.8184 despite an accuracy (0.6928) barely outperforming trivial majority guessing. This confirms that F1 must never be reviewed in isolation on imbalanced low-resource tasks without accuracy and confusion matrix inspection.               

05

Engineering Constraints & Open Limitations

              Every credible research log requires transparently documented boundary conditions. The conclusions of this project are scoped by several explicit real-world constraints:             

01 · HARDWARE CONFINES

                  Execution on a single mobile GPU (RTX 4050 6GB) limits max batch sizes and eliminates multi-GPU DDP gradient synchronization evaluation.                 

02 · EVALUATION SPLITS

                  Reported metrics reflect local GLUE validation matched subsets, not official withheld test server submissions, to ensure full deterministic seed reproducibility.                 

03 · SERVING DEPENDENCY

                  While task adapters compress to 3.57 MB, production inference pipelines still mandate loading the full 498.7 MB frozen RoBERTa base weights in memory.
