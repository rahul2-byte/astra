01
Problem Formulation

            Why I Built It: The Failure Modes of Single-Retriever RecSys           

            Standard recommendation architectures frequently rely on a singular retrieval paradigm: either collaborative matrix factorization or content-based embedding similarity. In production environments, both singular approaches exhibit critical, deterministic failure modes:           

emergency_home Collaborative Only

                Suffers catastrophic cold-start failure on long-tail catalog entries and new users. Fails when interaction matrices are >99.8% sparse, generating zero viable neighbors.               

find_in_page Dense Semantic Only

                Over-indexes on plot summaries. Recommends films with matching synopsis text while completely ignoring director style, genre pacing, franchise continuity, and user rating clusters.               

trending_up Popularity Graph Only

                Induces boring recommendation echo chambers. Surfacing solely high-frequency blockbusters destroys serendipity, user trust, and catalog discovery.               

The Production Solution: A decoupled two-stage recommendation funnel. Stage 1 executes broad, fast, high-recall retrieval across 4 heterogeneous streams (collaborative latent, dense bi-encoder, lexical keywords, and Bayesian popularity) consolidated via Reciprocal Rank Fusion. Stage 2 passes the normalized candidate pool to a point-wise LightGBM gradient-boosted tree with 32 cross-features to score true user engagement.           
02
System Topology

            The Two-Stage Recommendation Funnel           

            Scoring 25 million potential interactions with a complex GBDT in under 100 milliseconds is computationally unfeasible. The multi-stage pipeline reduces search complexity by pruning the space from 62,000+ candidate movies down to 400 preliminary candidates, fusing them to 100 deduplicated entities, and scoring only that high-signal subset with the reranker.

03
Candidate Generation

            4-Way Retrieval Funnel & Reciprocal Rank Fusion           

            Each retrieval stream produces an ordered list of 100 candidate movie IDs. Because the raw similarity metrics—cosine distances, SVD inner products, BM25 TF-IDF scores, and Bayesian ratings—are operating in entirely distinct mathematical domains with non-standardized variance, simple linear score combination leads to severe calibration distortion.           

                MATHEMATICAL FORMULATION: RECIPROCAL RANK FUSION (RRF)                Cormack et al.
              RRF\_score(d \in D) = \sum_{m \in M} \frac{1}{k + r_m(d)}             

              Where D is the set of all retrieved candidates across all streams, M represents the set of retrieval models (M = {SVD, FAISS, BM25, Bayesian}), r_m(d) is the 1-based rank position of candidate d in system m, and k=60 is the smoothing constant that bounds the outsized advantage of rank #1 over rank #2.             

pipeline/fusion/rrf_aggregator.py
Python 3.11 
# Reciprocal Rank Fusion implementation across 4 disparate retrieval channels
from collections import defaultdict
from typing import Dict, List, Tuple

def reciprocal_rank_fusion(
    retrieval_runs: Dict[str, List[int]],
    k: int = 60,
    top_n: int = 100
) -> List[Tuple[int, float]]:
    """
    Merges ordered candidate lists using RRF aggregation.
    retrieval_runs: dict mapping stream_name -> ordered movie_ids [m_1, m_2, ...]
    """
    rrf_scores: Dict[int, float] = defaultdict(float)
    
    for stream_name, rank_list in retrieval_runs.items():
        for rank_idx, movie_id in enumerate(rank_list, start=1):
            # Formula: 1 / (k + rank)
            rrf_scores[movie_id] += 1.0 / (k + rank_idx)
            
    # Sort candidates descending by aggregated reciprocal rank weight
    sorted_candidates = sorted(
        rrf_scores.items(),
        key=lambda item: item[1],
        reverse=True
    )
    return sorted_candidates[:top_n]
STREAM A TruncatedSVD

Collaborative Matrix Factorization

                Projects the 162,000 × 62,000 user-item interaction matrix into 128 latent dimensions. Captures implicit taste communities and user behavioral correlations even when titles share zero surface metadata.               

STREAM B FAISS FlatIP

Dense Vector Semantic Bi-Encoder

                Generates 384-dimensional dense vectors using sentence-transformers/all-MiniLM-L6-v2 over enriched plot synopses, thematic tropes, and character motifs for high-nuance semantic alignment.               

STREAM C BM25Okapi

Sparse Lexical Entity Index

                Constructed over tokenized directors, top-billed cast members, screenwriters, and curated folksonomy tag frequencies. Catches exact stylistic and personnel affinities that dense embeddings blur out.               

STREAM D IMDb Formula

Bayesian Popularity Baseline

                Applies weighted Bayesian mean ratings WR = (v/(v+m))×R + (m/(v+m))×C to filter out obscure, low-confidence entries and ensure that the candidate pool maintains baseline cinematic quality.               

04
Scoring Layer

            LightGBM Reranking & 32 Cross-Features           

            The fused candidate set of 100 movies is transformed into an inference feature matrix. The LightGBM gradient-boosted tree model performs point-wise scoring using 32 hand-engineered interaction features designed to detect subtle user-catalog synergies:           

User-Item Cross

Genre & Entity Affinity

  • • Jaccard genre similarity
  • • Director match binary & frequency
  • • Cast overlap score (top 5 billing)
  • • Historical rating bias for target genre
Candidate Specific

Catalog Metadata

  • • Log-transformed vote count
  • • Bayesian weighted rating (WR)
  • • Release era / Decade distance
  • • TMDB popularity velocity metric
Retrieval Metadata

Multi-Stream Fusion

  • • RRF aggregate rank score
  • • Retrieval stream presence bitmask
  • • FAISS dense cosine distance
  • • SVD matrix prediction score

                When a user submits only a single recent seed movie (n=1), the collaborative stream drops out smoothly while the BM25 and Dense FAISS bi-encoders maintain 100% precision without triggering HTTP error states or empty response arrays.               

06
Systems Engineering

            Engineering Constraints & Production Trade-offs           

memory                 Batch Offline Pre-computation vs Real-time Vector Search               

                Sentence Transformer embeddings (384 dimensions) for all 62,000 films are generated in offline batch pipelines and persisted into an indexed FAISS FlatIP vector catalog occupying 98MB of RAM. Real-time inference performs zero text encoding overhead—it looks up pre-indexed vectors for the seed movies and computes average centroid pooling in <1.8ms.               

dataset                 Memory Optimization for 25M Ratings Interaction Matrices               

                Storing the complete raw MovieLens rating sparse matrix exceeds 1.2GB uncompressed. Using SciPy csr_matrix with 32-bit floating point ratings combined with TruncatedSVD dimensionality reduction compressed the deployed runtime artifact down to 142MB without sacrificing singular value precision.               

timer                 FastAPI Latency Budget & Timeout Guarantees               

                The four retrieval streams run concurrently using Python’s asyncio.gather() with a hard 45ms timeout per channel. If the TruncatedSVD collaborative matrix lookup stalls under system load, the RRF aggregation proceeds gracefully with the remaining 3 streams, guaranteeing predictable sub-100ms client SLAs.
